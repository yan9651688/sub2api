# 0.2.3 迁移与回退边界

上游精确提交：8fa67d477d6651a744754392a8982ea589c26ae6。目标版本：0.2.3-llmrelay.1。

新增 236_group_model_allowlist_repair.sql，235、迁移执行器与 Ent schema 未修改。仅旧列时重命名；两列同时存在时，仅给新列默认空值补回旧配置；缺少新列时补建；最终保证新列 JSONB NOT NULL DEFAULT '{}'。已有非空新配置优先保留。

对于正常 0.2.2 数据库，该操作不改变分组业务值。对曾经不完整回退的数据库，它会原位修复字段而不恢复旧数据库快照。

此包只放行 deploy.py 常量中列出的旧/新提交与迁移指纹组合。回退至本次发布前的 0.2.2 应用镜像时，不反向改名，不删除 236 登记。直接降级到 0.2.1 不属于这个放行范围。

发布前验证要求：在内部网络的备份副本上比较迁移前后的业务表摘要、验证重复执行、验证遗留字段状态；启动新程序登记 236 后写入测试数据，再回退旧应用，确保数据保留且服务健康，最后再次升级；另执行自动换号、调度监控和健康失败自动回滚演练。实际生产备份、镜像与事务留在服务器发布目录，避免将业务配置或密钥提交到 Git。
